# Host source-completion fence

Formal completion is a host prerequisite, not an operation performed by the two-step game skill. The existing formal workflow freezes canonical original evidence, verifies all planned source passages and stores an immutable completion receipt. The UI's Create action can prepare this receipt automatically before game generation; it does not require a separate manual formal-memoir action.

The game model's chapter input is the composer's current saved prose, accompanied by the canonical timeline. Formal extractive passages are no longer substituted for composer chapters. The host additionally binds the current composer snapshot, root digest and revision so a newer manuscript invalidates an older job.

The host records private adaptation consent for the exact formal edition, checks current Shape and ownership, and fences stale jobs on source/policy/consent changes. These checks are enforced by application/database code, not prompts. Completion and consent do not claim a human game review. A valid two-step result is saved privately and opened in the UI without a review/publish form.
