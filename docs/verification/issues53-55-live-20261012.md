## Executed live cases and bounds

### Every-turn collector latency

The existing `profile_first_reply.py conversation --extended` campaign ran inside
the existing Linux private-worker container with Codex **0.156.1**. Task-owned
temporary scripts and homes were used. The 14 relevant source files were hashed
against the host checkout before and after execution; the container has no Git
metadata, so its own revision field is honestly null. The independently pinned
operator receipt supplies the revision above.

The campaign froze **42 foreground generations**, at most **84 app-server turns**,
a **120-second generation timeout**, a **1,200-second campaign deadline**, and
stop at the first failed generation. These are not a hard upstream token/spend
limit or an exact provider-request count. No replacement campaign ran.

Each language had ten matched cases: name-only first reply, later rich story,
resumed correction, narrator-identified photograph with unknown year, short
factual clue, long completeness stress input, entitled Family context, public
reference photograph, explicit interview-language change, and pause. One actual
candidate-history rollback followed in each language. Candidate history was
copied from the same baseline pre-turn state, preserving tenant file ownership.

Baseline: `gpt-5.6-luna-pooled` / max / legacy prompt. Candidate:
`gpt-5.6-luna-memoir-low` / low / legacy prompt. Read-only gateway and upstream-key
policy inspection confirmed the same underlying `gpt-5.6-luna` model and a key
enforcing low effort for the candidate; the shared max key was unchanged.

| Median over 20 matched cases per variant | Baseline | Candidate |
| --- | ---: | ---: |
| First meaningful public text | 15.4415s | 4.2915s |
| Validated question/reply completion | 21.988s | 5.6555s |
| Conversation saved, in-memory external adapter | 21.988s | 5.6555s |

All **42/42** results saved without public error events. First text improved in
**18/20** pairs; completion/save improved in **20/20**. Both pause cases asked
zero questions, and other cases asked one. Both rollback turns saved and retained
the language chosen in the prior candidate conversation. No production p95 or
absolute SLA is inferred from this small sample.

The 20 candidate public replies were inspected against the synthetic inputs.
Names, the mother/sister correction, uncertain years, sister-not-daughter
identity, public-reference boundaries, the final blue-envelope detail, language
changes and pause instructions were retained. This is a bounded public-reply
review, not comprehensive semantic equivalence, private-plan review, live
workspace extraction, image perception or proof of a real person's recall.
Context/cache footprints differ after route changes. Provider observations are
associated by time/order, not an exact application/provider UUID join; the
separate normal-route proxy smoke also generated requests in the observed window.

### Historical news discovery

A synthetic confirmed birth year of **1960** and birthplace **New York, USA**
produced the **1968–1975** hypothesis, including 1970. Geography remained
unresolved/tentative; no residence or personal 1970 event was created.

The real `HistoricalResearch` and `GatewayHistoricalProvider` used the existing
gateway, with the normal limits: two discovery requests, six source reads,
45-second total job deadline and one bounded same-query retry. Both outgoing
requests contained only:

```text
New York, USA 1968–1975 civic culture sport public events
```

The run ended in **6.330s** with `status=unavailable`, **2 discovery attempts**,
**0 source reads**, **0 eligible clues**, and `provider_unavailable`. Read-only
gateway observations show two HTTP 400 responses; upstream request logs record
two `invalid_request_error` outcomes. No successful search receipt, inspected
source, citation or historical question is claimed. Both error messages are
`Unsupported parameter: max_tool_calls`; the historical provider request includes
that parameter. This identifies the observed protocol blocker without asserting
that the remaining search protocol will work once it is removed. No expansion, alternative
provider, success cache entry, provider activation or new credential was used.
Cost metrics remain unavailable. The running API and private-worker images also
lack `skills/memoir-historical-news-research`, although it exists in the source checkout.
`MEMORY_SPARK_HISTORICAL_NEWS` remains unset in the running API. Source fixtures
therefore do not establish installed-skill or enabled live deployment parity.

The current source production webpack build passed under Node **24.0.0**. A
task-owned frontend on loopback port 3349 forwarded to the unchanged API on 8010.
The existing `smoke_conversation_proxy.py` ran with no API/auth/model replacement,
creating one synthetic anonymous project and retaining its three saved exchanges.

The task frontend was stopped after verification. The shared API and web both
returned HTTP 200 afterward, the private worker remained running, and no
task PostgreSQL fixture containers remained. The worker campaign directory was
removed. Both GitHub issues were read back as open; no issue comments or closure
