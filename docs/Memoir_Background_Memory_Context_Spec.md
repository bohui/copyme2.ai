# Repurpose memoir-memory-context for scheduled Lane B profile extraction

## Problem Statement

Memoir can already save narrator profile data, but its skill boundaries and active evaluation expectations do not match the canonical runtime. The owner has deprecated `app-auto-localization` because application code can select a supported language deterministically. The old `memoir-memory-context` skill still mixes language intake, interviewing, life-stage/place extraction, and avatar inference.

The storyteller should be able to supply supported personal profile details naturally in conversation. Those details should reach the user profile database without a separate form, repeated questions, or a profile model pass on every round. Previously parsed profile values should be available as reference, with their provenance and explicit-user authority preserved.

The latest requirement is broader than the earlier avatar-only proposal: keep the name `memoir-memory-context`, use it for supported narrator-profile parsing in Lane B, and run it at selected conversation milestones. The existing event and place skills retain their domains. Saving profile facts must not create competing event classifications, duplicate sources of truth, or background writes that overwrite newer explicit choices.

## Solution

Keep `memoir-memory-context` as the background narrator-profile parser. At a due checkpoint, supply the current authorized saved profile and all eligible conversation evidence not yet covered by a successful profile run. Produce a bounded, source-linked patch for supported personal profile fields, validate it in application code, and merge it into the canonical user profile database.

Exclude every field explicitly set or confirmed through the UI from automatic parsing targets. Its value can remain reference context, but the skill cannot propose a replacement. If the user manually confirms the entire profile in the UI, persist that decision and stop invoking this skill, including at otherwise due milestones. This stop survives new conversation turns, reloads, and worker restarts; only a later explicit UI action may re-enable automatic profile parsing.

Use rounds **1, 5, 10, 20, 30, and each subsequent multiple of 10** as the default schedule. This is the working interpretation of “1 then 5 round and then every 10 round.” Each run processes the accumulated interval since its last successful profile checkpoint, not only the newest message. Pending milestones can coalesce while preserving every unprocessed source. Failed runs remain pending.

Language stays in deterministic application code. Lane A continues to own the immediate reply and next question. Lane B's existing timeline owner manages scheduled profile work alongside the established event/place extraction lifecycle. Event and place extraction retain their normal per-source behavior; the profile skill is admitted only when its separate schedule is due. Reuse compatible extraction work where possible, with bounded background catch-up when an accumulated interval needs more than one page.

## Implementation Decisions

- **Skill purpose and name:** retain `memoir-memory-context`. Rewrite its discovery description and instructions around scheduled narrator-profile parsing in Lane B. Remove language detection, interview reply/question generation, and independent event-stage/place classification. Keep concise instructions for permitted reference context, source-grounded proposals, uncertainty, and completion.
- **Supported narrator fields:** inventory the actual profile schema, canonical settings writers/readers, and consumers before implementation. Initially cover the existing name, birth year, birth-date expression, birthplace, childhood place, and avatar-style concepts. Other already supported personal-data fields may be included when their meaning, validation, and authoritative persistence path are identified. The JSON profile's ability to hold arbitrary keys is not permission to invent fields or overwrite application state.
- **Application-owned exclusions:** UI/interview/source/book language selection, consent, access, entitlements, payment state, completed rounds, strategy/phase, delivery receipts, raw photo/map caches, and internal processing metadata remain under their existing authorities. The skill emits only an allowlisted personal-profile patch. The user's request to parse supported profile facts does not reinstate LLM language detection.
- **Early explicit-language short circuit:** determine whether the current viewer has an explicit UI/account or profile/interview language before first-reply detection. If an explicit choice exists, call neither `firstReplyLanguage()` nor `applyFirstReplyLocalization()`; returning early inside the latter is only a secondary race defense and is not sufficient. Preserve the existing meanings of UI and interview settings and their deliberate application-owned bridge: honor each explicit choice for its scope rather than introducing a new precedence rule. Pass the resolved interview choice through the normal request and backend selection path so narration in another language cannot overwrite it. Treat preferences still loading as unresolved, not as evidence that the user chose automatic inference. Existing explicit language-change actions remain authoritative.
- **Reference profile:** each run reads a current authorized projection of already saved values, field authority/provenance, explicit overrides, and profile revision. Use that state to preserve unchanged facts and distinguish additions, supported corrections, and unresolved conflicts. Saved or generated profile text is reference context, not new independent testimony, and cannot supply fabricated source citations.
- **Field-level UI ownership:** persist explicit user authority for fields set or confirmed through the UI, including deliberate blank/unknown values and explicit clears. Exclude these fields from the automatic target allowlist before building a request, rather than merely discarding writes afterward. They may remain in the reference projection. Manual protection lasts until the user explicitly releases that field through the UI; new narrator text, a model proposal, source changes, or a cadence milestone cannot unlock it.
- **Full manual-confirmation stop:** persist automatic profile parsing as stopped when the user explicitly confirms the whole supported personal profile, either through a confirm-all action or recorded UI confirmations that cover the complete defined field set. The latter is an application decision from explicit per-field confirmations, not an inference from populated values or model output. Once manually confirmed, no new invocation or profile-specific model call is admitted, even at due milestones. The stop survives additional rounds, updated schema/available fields, reconnect, rollback, and worker restart until an explicit UI re-enable. Do not automatically enroll newly added fields while the whole-profile stop is active.
- **Pre-dispatch gate:** before enqueue/claim where practical and again immediately before provider admission, check the current whole-profile stop and recompute remaining auto-eligible targets. A stopped profile or empty target set settles as an explicit skipped/manually complete state without loading the skill's model contract or making a profile request. Continue ordinary timeline/place/composer work normally; an existing timeline model request is not an invocation of this skill when its instructions/output targets are absent.
- **UI confirmation race:** include the current manual-authority/profile revision in request and commit fences. A UI-set field or confirm-all action occurring during inference invalidates any patch that could touch newly protected state. Cancel a pending request when possible; otherwise discard its stale proposal without effects. A call already admitted before the UI action cannot be unmade, but no later request or retry may pass the stop gate. Drain/cancel queued profile-only work idempotently and do not report discarded work as a successful parse.
- **Existing profile migration:** classify existing UI-origin values from authoritative write evidence where available. Preserve values of uncertain authority conservatively rather than assuming that a populated field is auto-editable or fabricating a historical confirm-all action. Keep field-level locks and the whole-profile stop as application-owned state that the model cannot create, remove, or modify.
- **Evidence scope:** admit all applicable original narrator source versions in the selected interval, with bounded prior evidence needed for resolving references or corrections. Attribute relatives and quoted speech correctly. Every proposed fact must cite exact owned original evidence; preserve approximate dates and original wording. A current unsupported inference cannot erase an explicit setting.
- **Canonical profile merge:** persist validated changes into the existing user profile database through a narrow canonical writer, not a wholesale model-generated JSON replacement. Merge only accepted fields that remain in the current auto-eligible target set against the current revision. Reject a proposal for a UI-owned field, even if its value equals the current value. Preserve unrelated state. Omission is no change; an empty successful patch may advance actual covered evidence without changing values. A manual skip is recorded separately and must not claim that unparsed evidence was model-processed. Deletion or invalidation requires an authoritative reason.
- **Existing schema gaps:** the legacy profile parser accepts birth-date expressions and avatar style, while the current canonical settings API/SQL expose a narrower field set. Reconcile the supported personal-data contract, read projections, and manual-override path where required. Keep provenance and checkpoint metadata narrowly scoped rather than adding a generic profile subsystem.
- **Name ownership:** reuse and extend the existing chosen-name authority/revision mechanism for any B proposal. Preserve immediate literal name handling in A's reply-only path and explicit name settings. The delayed profile parser must not create a competing preferred-name store or overwrite a newer A/manual name decision.
- **Domain projections:** `memoir-author-timeline` remains authoritative for MemoryEvent identity, event life stage, timing, and chronology; `memoir-place-journey` remains authoritative for eligible geographic cues. A birthplace or childhood-place profile field represents that location's stated relationship to the narrator. Reuse validated events/places and their original evidence where available, rather than independently inventing dates, stages, geographic identities, or coordinates. Any existing story-focus compatibility projection must follow those owners instead of adding a second classifier.
- **Avatar inference:** use clear narrator self-identification only for the existing artwork hint, currently male/female styles. Preserve narrator-versus-relative attribution and omit ambiguous or conflicting inference. Voice pitch/timbre, accent, image appearance, and birthplace do not determine the hint. Explicit artwork choices win; this task adds no independent demographic record or artwork categories.
- **Default schedule:** trigger normal profile work after completed rounds 1 and 5, then every tenth completed round: 10, 20, 30, 40, and onward. This is a profile-specific schedule, separate from the five-round composer cadence. Keep the schedule deterministic and independently configurable without adding a new UI. Reopening, technical replay, retries, and background completion do not increment the conversation ledger or restart onboarding.
- **Coverage intervals:** the ordinary windows are round 1; rounds 2–5; rounds 6–10; rounds 11–20; rounds 21–30; and so on. These are coverage targets, not a requirement to launch one invocation per milestone. If the round-five run fails and round ten becomes due, catch up from the last successful profile boundary through ten, including the unfinished two-to-five interval.
- **Source cursor versus round target:** use completed rounds to decide when a normal profile run is due, but use canonical source sequence/version coverage to determine what it must read. Freeze the source frontier for the selected completed-round boundary. Include applicable accepted originals without saved replies when they lie in that covered interval; keep later accepted evidence pending for the next eligible target. Track source edits independently so a low-sequence changed source cannot disappear behind a completed cursor.
- **Independent successful profile progress:** persist requested target, successful covered round/source frontier, source-version dependencies, and bounded page progress for this profile task. Existing timeline extraction success does not imply profile parsing success. Claiming, invoking a model, timing out, or writing only part of a checkpoint must not claim full profile coverage. Maintain an explicit pending/failed state until the required work commits.
- **Reuse B ownership:** manage profile work through the existing durable project timeline B owner and its outbox/claim/retry infrastructure. Do not create a second concurrent profile writer or mutable shared execution transcript. Loading the profile skill is conditional on due work; ordinary event/place extraction between profile milestones must not silently run this skill.
- **Bounded checkpoint processing:** share an eligible B request when its evidence packet covers the required profile interval. The current timeline worker normally extracts one bounded source window, so enabling the skill only for the newest checkpoint message would miss intervening facts. Revisit uncovered originals in bounded resumable pages when necessary, reusing already committed event/place results instead of duplicating their effects. Additional profile parsing calls are limited to due catch-up work; no mandatory profile call is added to every conversation round.
- **Reply-only and empty intervals:** preserve the existing no-model reply-only behavior and A's literal name handling. A due interval with no eligible unparsed content may settle deterministically with an empty profile patch. A greeting/name-only round is not a reason to add a classifier. It is still included in honest coverage accounting.
- **Coalescing and retry:** one active B owner processes the frozen profile interval while newer milestones update a durable newest-requested target. A later run resumes after committed profile coverage, includes failed ranges, and reuses completed pages idempotently. Bound attempts, queueing, lease lifetime, model input, and worker quantum using the existing infrastructure. No source or milestone is considered processed merely because the timeline/composer caught up.
- **Manual edits and invalidation between checkpoints:** direct profile edits, source withdrawal, privacy changes, and dependency invalidation take effect through application code immediately. Fence or remove invalid derived values without waiting for the next generative profile run, while preserving independent explicit UI values and the whole-profile stop. Do not force a profile-model run on every correction/privacy event or reopen a manually stopped skill. Eligible narrated additions/corrections for unprotected fields remain pending for the next checkpoint unless the existing authoritative edit path already resolved them.
- **Fenced commit:** validate source scope/versions, source dependencies, current policy, profile/field authority revision, snapshot, page digest, and B token at commit. A stale page cannot overwrite a newer explicit setting or correction. Committed profile effects and page receipts must agree atomically; full successful coverage advances only after all required pages commit. Define how project-scoped evidence projects into the owner profile and reject unrelated-account/project writes.
- **Foreground independence:** A keeps its current message, authorized context, immediate policy/correction handling, single normal collector call, and selected question. It may read the latest committed profile but never waits for routine profile catch-up. Deliver profile/workspace changes through existing authorized refresh surfaces; a pending update must not inject new state into an in-flight reply or disrupt recording.
- **Cleanup and observability:** retire unused LLM-language helpers, schemas, fallbacks, and active evaluation cases after checking callers. Preserve the owner's localization archival and working deterministic locale code. Exclude deprecated localization from active discovery/dispatch. Update memory-context probes to check profile values, saved-reference use, due/skip decisions, covered intervals, proposal validation, and committed effects. Retain immutable historical evidence and redacted correlation; do not log private profile/source contents.
- **Rollout:** preserve two-lane disabled/rollback compatibility, current round allowance, composer cadence, and production flags. Schema changes and activation belong to the later reviewed implementation. Updating this specification does not implement the schedule, deploy code, or enable production processing.

## Testing Decisions

- **Primary acceptance boundary:** retain the existing authenticated canonical conversation API → actual Lane B worker → persisted profile readback seam discussed with the user. Use real orchestration and native disposable PostgreSQL with controlled provider results. Extend this boundary for scheduled profile work rather than introducing a new profile service or standalone prompt-string tests.
- **Observable behavior:** submit narrator sources, observe A's saved reply/question, execute due B work, and read the profile through the authoritative authenticated projection after reload. Verify accepted values, preserved explicit fields, exact evidence dependencies, separate pending/covered states, and real dispatch/call counts. A loaded file, generated patch, or synthetic skill trace alone cannot prove persistence.
- **Cadence matrix:** verify profile admission at completed rounds 1, 5, 10, 20, and 30 and absence of routine profile calls at 2–4, 6–9, and 11–19. Keep ordinary timeline/place processing running between those milestones. Test reopen, retry, failed A reply, existing high-round sessions, and worker restart without resetting counts or replaying every historical milestone.
- **Accumulated evidence:** introduce a birth fact only in round two and another only in round seven; verify they are picked up at five and ten respectively. Include explicit changes to previously processed lower-sequence sources, accepted-without-reply originals inside the frozen interval, long Unicode messages, and bounded multi-page windows. No checkpoint may report full coverage after processing only the latest source or a partial page.
- **Saved-profile reference:** seed a profile with known facts, explicit overrides, uncertainty, and a revision. Verify the parser receives the authorized reference projection, preserves unchanged values, fills supported missing fields, and handles conflicting narrator evidence without broad replacement. Test another manual edit while the model is running; stale writes must fail or reconcile through current authority.
- **Manual-target exclusion:** seed a mix of automatically parsed, UI-set, UI-confirmed blank, and unfilled eligible fields. Observe the actual admitted request: manual values may appear as reference but must be absent from writable targets. Reject an output attempting any excluded field without changing its value, confirmation metadata, or other profile state. Confirm that explicit unprotection makes only the selected field eligible again.
- **Whole-profile stop:** manually confirm the complete profile before each of rounds 1, 5, 10, and 20, while work is queued, during provider admission, and during an in-flight call. Verify durable suppression of new skill contracts/calls and retries, safe rejection of stale results, and honest skip status. Repeat after reload/worker restart, later rounds, schema additions, and profile edits; none may automatically reactivate parsing. An explicitly authorized UI re-enable is the only resumption path.
- **No remaining targets:** verify that explicitly confirming the last outstanding field latches the durable whole-profile stop, even without a separate confirm-all click. For other cases with no auto-eligible targets, verify a due checkpoint skips model work without inventing a historical manual-confirmation event. Preserve the distinction between an empty target set, explicit whole-profile stop, empty successful extraction, and failed work. Verify normal event/place/composer jobs continue and that their calls are not misreported as profile-skill execution.
- **Personal-data matrix:** cover names, birth years and approximate expressions, birthplace versus childhood/current place, avatar self-reference versus relatives, mixed/quoted speech, unknown fields, and English/Chinese reviewed transcripts. Reject unsupported keys, fabricated evidence, language mutations, coordinates, and application-state changes. Validate name handling against the existing canonical chosen-name path.
- **Retry and coalescing:** fail the checkpoint-five run, then make ten due and prove catch-up includes every source after the last successful profile save. Block B through several milestones, allow one claim, and verify a coalesced newest target with no lost source/version changes. Exercise duplicate receipts, changed retry bodies, worker crashes, old tokens, partial-page rollback, and identical replay without duplicate values or conversation rounds.
- **Privacy and projection:** test account/project isolation, explicit-choice precedence, source edits/withdrawals, policy changes, removed evidence, and revision conflicts. Verify invalidation takes effect between scheduled runs without an extra profile model call. Readback must omit invalidated derived fields while preserving unrelated facts and existing explicit settings.
- **Foreground and downstream regression:** hold or fail scheduled profile work while A completes meaningful text, its chosen question when applicable, and conversation save. Preserve deterministic locale/first-reply/explicit-change behavior, reply-only model skipping, recording-safe UI state, timeline/place ownership, and five-round composer behavior. Existing two-lane barrier, native persistence, progressive composer, and locale-bridge tests provide prior art.
- **Zero-call locale regression:** through the actual conversation submission/UI boundary, observe calls to both first-reply routines. For explicit UI/account selection with an otherwise empty conversation profile, and for explicit profile/interview selection, assert zero calls to `firstReplyLanguage()` and `applyFirstReplyLocalization()`. Cover English/Chinese with opposite-language input, typed/reviewed voice input, reload, delayed preference hydration, account switching, and a manual change racing submission. Check the resolved language reaches the backend and the explicit settings remain unchanged. Keep a positive automatic-mode case proving the first-reply fallback still works when no explicit selection exists. Do not claim this property merely because the localization helper returned false or the final displayed language stayed unchanged.
- **Skill/evaluation acceptance:** validate the renamed-purpose instructions while retaining the skill name. Replace language-only, avatar-only, and every-round memory-context assumptions with due-checkpoint profile cases. Check actual source coverage, saved reference values, valid patches, and commit receipts. Controlled proposals prove mechanics and validation, not live model semantic quality or a latency improvement.

## Out of Scope

- Renaming or retiring `memoir-memory-context`.
- Reintroducing LLM locale detection, changing existing locale precedence, adding languages, or translating original sources/book editions.
- A general model-writable JSON profile, new unsupported personal-data categories, new artwork categories, or model changes to consent/access/entitlements.
- Independent event-stage/time/geographic extraction, duplicate MemoryEvents, remapping places, or a second canonical biography index.
- Moving question selection out of A, changing strategy planning, or delaying immediate privacy/explicit-setting changes until a profile checkpoint.
- Letting a model infer manual profile completion, unlock UI-owned fields, re-enable stopped profile parsing, or treat conversation text as authorization to reverse those choices.
- A separate profile service, a second concurrent B owner, or mandatory profile parsing every round.
- Changing the five-round composer schedule, free-round allowance, publication gates, or other skills' domain ownership.
- Unrelated Family-tree/game/research work, broad repair of existing failed tests, or rewriting historical evaluation artifacts.
- Production migration/deployment, paid/live-provider campaigns, or automatic rollout enablement.

## Further Notes

The owner's latest instruction on 17 October 2026 supersedes the earlier avatar-only version of Issue 75: parse supported user-profile facts automatically from conversation, use already parsed values as reference, retain the name `memoir-memory-context`, and reduce its invocation frequency. The default interpretation is milestones 1, 5, 10, 20, 30, and onward, rather than 1, 5, 15, 25. Routine profile processing is separate from every-source timeline/place extraction and five-round progressive composition.

The owner additionally requires UI-set fields to be excluded from parsing targets and full manual confirmation in the UI to stop this skill entirely. These rules are dispatch gates as well as write protections; preserving a value only at merge time does not satisfy the requirement to avoid unnecessary skill calls.

The same pre-dispatch principle applies to existing deterministic localization: an explicit UI or profile language must skip both first-reply routines entirely. Current submission code checks the configured conversation language before detection, while a UI-only fixed preference is guarded inside the localization helper. Moving that authority check ahead of both calls is a required compatibility fix; this specification does not claim it already exists.

Related work remains [Issue 70](https://github.com/bohui/copyme2.ai/issues/70), [Issue 6](https://github.com/bohui/copyme2.ai/issues/6), and deterministic localization under [Issue 1](https://github.com/bohui/copyme2.ai/issues/1). Existing ownership, acceptance criteria, and production rollout controls remain applicable.

Inspection used local main at `e060029`, preserving the owner's uncommitted localization-skill archival. The profile JSON store and older parser support more personal fields than the current canonical settings allowlist; the timeline worker normally reads bounded single-source windows and its existing scheduler has no profile-specific 1/5/10/20 cadence or successful profile cursor. Implementation therefore needs coordinated instruction, bounded worker, canonical persistence/read-projection, and scheduling changes. Editing the skill file or reusing the composer cadence alone will not satisfy this requirement.

This task updates and republishes the specification in the existing `ready-for-agent` issue. It does not implement application or skill behavior, run a live model evaluation, or enable production processing.
