## Implemented result

B can propose a versioned comfort/explore/shape plan within the existing unique,
coalesced project timeline lane. Application transactions own proposal validation,
monotonic revisions, source/policy/snapshot fences, candidate provenance and retry
receipts. Shadow plans stay private, including isolation from the legacy candidate
reader. Reply-only B work uses no model and does not infer a new strategy.

Opted-in A reads one active plan or the bounded legacy adapter, projects a shared
core plus one strategy module, and returns one immediate question or no question
with its existing work hint. It generates no future pool. A may deviate for the
latest redirect/correction/pacing/pause/direct answer without rewriting B's plan.
Legacy explicit preferences and all composition permissions remain separate.

An outcome is saved atomically with the canonical reply, initially undelivered.
Successful final governed ASGI send marks delivery under the existing live lease
and publication fence. Failed sends leave candidates unasked; cached replay can
recover delivery without a new call/source/round. A reads an explicitly authorized
prior delivered question. Policy/source invalidation purges private derived bytes
but retains a safe strategy enum hint. Existing public NDJSON and independent
workspace readiness behavior remain compatible, with no mode controls added.

The two bb59 follow-up findings also have native/API repairs: A validates its
pinned plan dependencies without adopting newer optional B plans, and direct
controls after reported clauses remain authoritative while quoted controls do
not. Disabled planning delegates without redundant canonical page preparation.
All five original reported review counterexamples have native tests and repairs: complete
original coverage before checkpoint replacement; durable maintenance on reclaimed
source-less pages; shared pending-source protection after flag rollback;
privacy-based place validity across language-only preference changes; supported
B model aliases. See the architecture document for exact limits.
