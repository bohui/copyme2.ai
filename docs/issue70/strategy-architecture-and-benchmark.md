## Profile and bounded design

A's existing canonical runtime/context/engine still owns authorization, accepted
originals, complete watermark + tail, current literal policy, bounded model
admission, reply save and publication fences. Default cold execution is retained.
The extension adds one owner-scoped plan read to opted-in A. It removes future
pool generation from that A contract, projects shared collector policy plus one
small strategy module, and adapts a zero/one-question output back into the existing
plan/save/photo/continuity transaction. There is no third classifier call.

B remains the one existing project timeline lane, with conditional work, durable
coalesced targets, canonical page receipts and reserved worker capacity. Its
existing extraction call can also propose comfort/explore/shape, a bounded
objective, active focus IDs and up to five exact-source-grounded candidates. No
filler minimum exists. Reply-only work makes no B model call and proposes no
strategy change; it cannot infer a downgrade from a short answer or pause.

A new versioned InterviewStrategyPlan is separate from PhaseState, preferred_phase,
consent and composition authority. The SQL transaction validates the canonical
page digest, source/version, policy/preference, phase, execution generation,
snapshot, event revisions and a monotonic plan frontier. Stale pages and changed
retry bodies reject without effects. A's one-turn deviation records a reason and
used strategy; it does not update B's plan. The explicit legacy phase remains a
pacing constraint. Automatic internal shape only clarifies order, identities or
links; it changes no organiser/composer, entitlement, opt-in, publication or print
permission.

Shadow proposals are private and cannot enter either the active plan reader or
the legacy prepared-question reader. Activation requires all existing two-lane
controls, `MEMOIR_INTERVIEW_STRATEGY=1`, collector variant `two-lane-v1`, and the
private database strategy control with shadow disabled. Defaults remain OFF /
shadow. Turning any selector control off restores the legacy collector contract
and preserves existing explicit pacing. No production control was changed.

The outcome transaction stores exactly the saved immediate question, selected ID,
plan_revision_seen, controlled reason, used strategy and work hint. It starts
undelivered. Only successful final governed ASGI send triggers the idempotent
delivery writer under the still-held foreground lease/fence. A failed send leaves
it undelivered; exact cached replay can finish the receipt with no model/source/
round duplication. Asked filtering uses actual new delivery receipts; legacy
questions retain their prior compatibility treatment. A receives the latest
currently authorized delivered question separately from saved raw-tail replies.
Policy/source invalidation removes private plan/question bytes while retaining a
safe strategy enum hint so corrections do not reset the journey.

The frontend still receives the existing NDJSON events. Workspace readiness is
independent of the saved reply, and the extension adds no visible mode controls.
20 free turns, configured five-round private draft cadence/opt-in, and the
7,000-word cap remain under existing server-owned gates.

## Five review repairs

1. A checkpoint is marked lossless only if all active original windows and the
   complete predecessor evidence fit its existing bound. A raw inventory/hash
   cannot replace testimony. All remaining sources stay mandatory in A's complete
   tail. More than sixteen evidence windows reports summary_pending and publishes
   no lossy checkpoint; A fails closed if complete required context cannot fit.
2. A complete source-less B page carries a server-derived durable maintenance
   obligation, so reclaim still finishes its bounded proof before settling.
3. The canonical acceptance path enforces pending-reply reconciliation even after
   two-lane flag rollback.
4. Accepted place facts compare current privacy digest/policy and exact source,
   rather than invalidating solely on unrelated language preference revisions.
5. B checkpoint configuration admits existing memoir-luna-low and legal2ai-luna-low
   aliases, consistent with the existing bounded lane model contract. Foreground
   model admission remains unchanged.

The semantic-summary replacement for an arbitrarily large raw interval is still
unimplemented. Explicit pending behavior is a correctness repair, not evidence of
complete long-history acceptance. It remains a release gap.

## Frozen matrix and limits (no dispatch authorization)

Before any later live run, pin immutable baseline/candidate SHAs, Codex 0.156.1,
adapter, effective model/effort and database snapshots. Use the previously planned
foreground alias gpt-5.6-luna-memoir-low and the same B configuration for each
matched pair; record effective routing. Cover all three internal strategy
profiles in English and Chinese; name-only, rich first, short, resumed/correction,
explicit question, pause, language change, pending upload and long 23+ turn
scenarios; B normal, blocked and failed. First-turn profiles may have no stored
plan and use the bounded adapter; never manufacture a forced strategy sequence.

Five matched pairs per scenario/language/B condition/strategy profile yields at
most 810 pairs / 1,620 A calls and 1,620 bounded B calls. Randomize AB/BA order.
Keep 120s A, 600s B and 90-minute campaign deadlines, no automatic campaign
retries, 65,536 input-byte upper bounds, 8,192 A / 16,384 B output headroom. Repairs
count against ceilings. A funded total cost ceiling and explicit live dispatch
authorization are missing; the matrix cannot run yet.

Target: at least 30% lower median time to first meaningful public text versus the
matched baseline, with useful-question, save, grounding, privacy and correction
quality retained. This is a target, not an achieved result or SLA. Record paired
median/p95/distributions, failed cases, full useful-question completion, save,
first playable audio where available, B lag, repeats/inappropriate questions and
usage/cost. No-question cases are not counted as a question-latency win. Blind
semantic review must inspect originals and latest intent.

Redacted server observations correlate client turn ID, source sequence, planned/
used strategy, plan revision/age, candidate use/override reason, correction flag,
repeat counts, context/model/save durations, first successful meaningful text
send and full question. Source/question/name/photo bytes are never logged by this
observer. Actual provider usage/cost and playable audio are unavailable in this
adapter and remain null. Synthetic barriers prove ordering and contract behavior;
controlled provider proposals and source-frontend fixtures do not prove live
semantic decisions or a speed improvement.
