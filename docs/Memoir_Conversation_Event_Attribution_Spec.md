# Ensure complete conversation-to-event attribution with grounded time and place links

Repository specification (relative path): `docs/Memoir_Conversation_Event_Attribution_Spec.md`


## Problem Statement

The storyteller should be able to continue an episode across several replies without repeating its age, period, or location. Every accepted reply must be accounted for, but this must not require an unconditional timeline/place model call, create a new event for each reply, or force greetings and conversation controls into biographical events.

The current canonical path already saves versioned narrator sources, reconciles source evidence into MemoryEvents, supports uncertain temporal placement, and records durable evidence roles for stage progress. However, successful source processing can legitimately return no events; it does not prove that all narrative passages have been attributed or deliberately left unresolved. In enabled two-lane execution, reply-only work avoids the extraction model, while other unprocessed bounded source windows enter extraction. A general cheap continuity-association and selective catch-up path is not yet established.

Places currently arrive as source-grounded place journeys stored against the source message. Sharing a source with an event does not establish which mentioned place belongs to which event, especially when a reply discusses several episodes, a move, or another person's experience. The composer consumes existing events and original evidence; it must not become a fallback event/location extractor.

The missing guarantee is complete, inspectable conversation attribution with grounded event context, not mandatory event, age, or location values for every message. Unknown placement and genuine non-story replies must remain valid, and contextual navigation links must not be promoted into factual evidence or stage-progress volume.

## Solution

Extend the existing Lane B timeline/attribution workflow and canonical source/event records. Account for each accepted narrator source and its relevant passages with durable dispositions such as pending, linked, non-story, or unresolved. Preserve the distinction between work attempted, evidence accounted for, and attribution actually resolved. Link meaningful testimony to one or more canonical events using exact original source versions and spans; retain unresolved material instead of silently dropping it or manufacturing a match.

Reuse established event context for clear continuations where existing application-owned evidence makes the association unambiguous. Use contextual associations only for their declared purpose. New claims, corrections, topic changes, and uncertain associations require validated Lane B reconciliation. Coalesce pending evidence into bounded catch-up work when appropriate, without a new classifier, new skill, or every-N-round schedule. Evaluating lightweight rules after a reply is not the same as invoking extraction after every reply.

Associate supported time/age and place roles with the appropriate event, retaining their original evidence and uncertainty. A read can then follow a source passage to its event and authorized time/place context without copying those facts into every message. Place journeys remain workspace navigation aids, not independent proof of residence, identity, or an autobiographical event. The composer stays downstream and writes only from authorized evidence.

Attribution is independent of the AI's comfort, explore, or shape interview mode. Those modes guide Lane A's reply; B can propose the next planned mode in its existing eligible extraction/planning call. Mode selection is automatic under Issues 70/76, with no user mode control or extra classifier call. Mode changes neither admit/suppress attribution nor establish an event, time, or place. Ordinary topic, pacing, privacy, correction, and stop requests remain meaningful narrator intent; recognizing them does not let the user select a mode enum or discard narrative passages in the same reply.

Implement this after [Issue 75](https://github.com/bohui/copyme2.ai/issues/75) and before the orchestration consolidation in [Issue 76](https://github.com/bohui/copyme2.ai/issues/76). Use the existing Lane B infrastructure; this ticket must not wait for the entire orchestration refactor or duplicate either ticket's ownership.

## Implementation Decisions

- **Ownership and seam:** deepen the existing canonical timeline/attribution module under Lane B. Its application-owned interface accepts authorized source/change references, reconciles source-to-event/time/place attribution, and exposes bounded persisted outcomes. Reuse current canonical writers, source IDs/versions, event IDs/revisions, evidence links, and read interfaces. Do not build a second event index, generic workflow platform, standalone attribution skill, or full foreground classifier. Independent composer and profile responsibilities remain with their owners.
- **Current implementation evidence:** source acceptance is already durable and versioned. The timeline writer already stores many-to-many event/source evidence, and the temporal contract supports age/uncertain placement. Empty extraction is valid and source processing can succeed without event links. Enabled two-lane extraction adds source-keyed place journeys in the same bounded pass; these are not a complete event/place association model. Existing stage attribution distinguishes direct narration, stage evidence, dependencies, and conservative legacy roles. Preserve these working behaviors rather than label all attribution missing.
- **Coverage and dispositions:** add the smallest durable attribution state needed to distinguish pending, linked, non-story, and unresolved material, while retaining existing processing/retry state. Cover relevant source spans, not merely a whole-message boolean. A partly linked reply must expose remaining pending/unresolved passages. Distinguish decision/attempt coverage from resolved semantic attribution; an empty result or contextual link cannot silently advance a fully resolved frontier. Linked means the passage-to-event association is established, not that its age or place is known: missing optional placement can remain explicitly unknown without keeping a valid link pending. Privacy-withheld/excluded material retains its existing policy disposition and is not relabeled non-story. Unresolved work has an explicit bounded reason and does not spin indefinitely while waiting for evidence or user clarification. These are attribution outcomes, not new model-selected conversation modes.
- **Source authority:** account for accepted narrator sources independently of successful-round counting. Failed assistant delivery must neither discard accepted evidence nor manufacture a completed round. Assistant questions/replies, generated summaries, public references, map imagery, and earlier prose are not narrator testimony. A source may support zero, one, or multiple events; a genuine non-story result is valid. Preserve transcript/source lineage and existing recording behavior without expanding the voice workflow.
- **Context versus evidence:** store or project a contextual navigation association distinctly from direct factual evidence. Reuse the actual delivered-question/event reference, existing validated reply linkage, and current source/policy scope only when application rules establish unambiguous continuity. A most-recent event, similar title/place, or model suggestion alone is insufficient. Context-only links cannot add facts, establish age/place, satisfy story coverage, confirm all details in a question, or count as direct stage narration. A short reply carrying new facts still needs validated reconciliation; do not claim every continuation can safely bypass the model.
- **Selective rule-driven processing:** run lightweight deterministic admission/continuity checks without an extra LLM call. New or changed testimony, uncertain identity/continuity, relevant corrections, and changed source/policy dependencies trigger Lane B reconciliation. Use the existing small A work hint and validated context as inputs, not irrevocable permission to ignore narrative evidence. Preserve reply-only no-model handling for genuine no-story inputs. No new per-reply model classifier and no periodic timeline/place schedule are introduced. Only composer and memory-context remain periodic under Issue 76's policy.
- **Interview-mode independence:** comfort/explore/shape selection belongs to the existing LLM strategy calls and validated plan/outcome contracts owned by Issues 70/76. B may propose a next-turn mode during the same eligible reconciliation call; that proposal is separate from attribution effects. A mode-only change, legacy PhaseState, or preferred_phase must not enqueue/suppress attribution, reset its frontier, manufacture an event, or change grounding rules. work.mode reply_only/extract and pending/linked/non-story/unresolved dispositions are different concepts from interview mode. Reuse current source/content/policy rules in all three modes, honoring actual narrator wishes without adding regex mode selection, user enum controls, or another classifier. A legitimate no-story/reply-only B skip must not require a model call merely to update an interview plan.
- **Bounded catch-up:** coalesce eligible pending evidence and reuse committed unchanged effects instead of replaying successful extraction. Batch only within existing source/window, packet, model-budget, and evidence-validation constraints; paginate larger intervals and expose incomplete coverage. Every proposed link must identify the correct original source version and exact supporting span, including Unicode offsets and repeated-quote ambiguity. Combining sources must not drop originals, infer continuity from adjacency, widen the current authorization, or bypass the canonical page/commit fence. Work may still need separate bounded calls when dependencies or budgets require them.
- **Stable event reconciliation:** enrich an established event only when exact evidence and validated continuity justify its identity; retain separate occurrences and period records. Use expected event revisions and canonical IDs, preserve unresolved candidates and conflicting attribution, and prevent replay from creating duplicates. New narration may link to an old event without changing unrelated events. A cheap association cannot bypass explicit removed-link exclusions or author overrides.
- **Time and age:** retain existing temporal expressions, precision, original evidence basis, stage evidence, and supported chronology. A linked message can reference its event's established placement rather than duplicate a new date claim. Calculated age/year values require valid narrator-specific anchors and declared precision; relatives' dates, capture order, current age, assistant suggestions, or a saved profile value without usable authority are insufficient. Issue 75 owns profile provenance and protected values. Reuse available authorized profile evidence where valid, but retain unknown placement when it is missing, conflicting, outside the bounded packet, or not yet parsed; do not wait for another periodic profile checkpoint or force an inference.
- **Event/place associations:** extend existing canonical attribution with bounded event-to-place associations where the narrative establishes a role such as the event setting, move origin, or destination. Tie each association to the relevant event, original source/version/span, semantic role, and current revision/policy validation. A place cue or geocoded center alone does not establish any personal role. Several events/places in one source require selective associations, not a Cartesian product. Unassigned mentions remain cues or unresolved context. Keep private premises out of public map targets under the existing coarse-place policy.
- **Place journey compatibility:** maintain the distinction between a canonical personal claim and a place journey used by the workspace. An established event setting can supply authorized contextual readback for a clear continuation without emitting a fresh journey or repeating geocoding/photo research. New journey activation still requires current qualifying narrator place evidence under its existing contract. A mere reference such as there must not fabricate a new named-place marker, residence claim, photo association, or map coordinate.
- **Corrections, privacy, and manual authority:** preserve current source edits/versions, withdrawal, event corrections, actor/origin authority, and explicit exclusions. Changes invalidate only their affected derived associations and coverage; stale work cannot restore removed links, resolve conflicts silently, or overwrite a newer correction. Recheck account/project, source/event revisions, privacy/policy, and lane ownership at admission/read/commit. Do not retain withdrawn source text in newly introduced attribution records; expose only policy-permitted identities/status. Event attribution cannot write protected profile fields or re-enable profile parsing stopped under Issue 75.
- **Stage-progress compatibility:** preserve durable direct-evidence roles, accumulation across enrichment, explicit-stage corrections, overlap union, eligibility of saved replies, and conservative handling of legacy roles. Context/navigation associations and reused temporal/relation background must not become primary/stage evidence or increase narrative word volume. Keep stage percentages and their existing formula unchanged. A source with no narrative event may still be eligible personal-profile evidence for Issue 75; non-story classification here cannot suppress that independent workflow.
- **Composer integration:** composer reads canonical events, original testimony, attribution completeness, and authorized time/place context; it does not extract, merge, or retag events. Supported unplaced/undated material can remain usable under existing writing rules. Unknown optional placement does not block all prose, but pending/unresolved source coverage cannot be advertised as fully resolved or silently omitted from coverage reporting. Preserve extraction-complete snapshot requirements, protected writing, cadence, and publication/consent gates. Do not rerun composer simply to repair attribution status when prose dependencies are unchanged.
- **Readback and observability:** extend existing authorized collection/source/event reads and worker receipts with bounded per-source/passage dispositions, linked event references, applicable time/place references, unresolved reasons, and current revisions/coverage. Page large link sets rather than flatten a lifetime into one response. Differentiate pending work, unresolved interpretation, non-story handling, context-only association, and committed direct links. Expose no private reasoning or raw transcripts in shared telemetry. Issue 76 owns unified thinking-step rendering and runner orchestration; this ticket supplies truthful persisted attribution outcomes and compatible progress evidence.
- **Upgrade and rollout:** preserve existing IDs, links, overrides, stage roles, and composer dependencies. Reuse provable existing evidence to initialize attribution conservatively; absent or irrecoverable historical roles remain legacy/unresolved, not guessed. Any required source reconciliation is bounded, current-policy-authorized work, not an unlimited model-backed migration. Keep rollout/flag-off compatibility and replay-safe schema evolution. This ticket specifies implementation and disposable-data acceptance, not authorization for production backfills, provider campaigns, or deployment.
- **Ticket responsibilities:** Issue 75 establishes profile/manual-authority handling first; this ticket establishes attribution semantics next; Issue 76 consolidates background dispatch/eligibility and thinking-step presentation afterward. This workflow must work on the existing Lane B infrastructure before broad consolidation. Agree the small integration contract with Issue 76 without copying its skill map or scheduling rules. The published ticket does not implement any of these changes by itself.

## Testing Decisions

- **Confirmed primary seam:** the user confirmed the existing authenticated conversation interface through the actual Lane B worker and canonical persistence into owner-authorized attribution readback, including blocked-B, retry, and restart cases. Extend this flow rather than introduce a parallel test-only dispatcher. Use disposable PostgreSQL and controlled provider/transport adapters at the existing external seam; do not substitute pre-seeded final links for the writer behavior under test.
- **Observable acceptance:** submit original replies, drive real admission/worker/commit behavior, reload through a fresh authorized read, and inspect source/event/time/place identities, versions, dispositions, coverage, and actual provider admission. Assert user-visible data guarantees and exact persistence effects rather than prompt strings, import paths, internal helper counts, or synthetic success labels. Controlled provider outputs establish orchestration/validation behavior, not live model quality; keep that distinction explicit.
- **Continuation example:** start with an evidenced bicycle accident at age twelve in Chengde, then accept a clear follow-up such as my father helped me up. Verify the new testimony is attributed to the appropriate existing episode, retains the old grounded time/place context, and does not create a duplicate event or fresh place journey merely because another reply arrived. Observe any required reconciliation calls honestly; do not equate event reuse with zero model execution. A truly context-only reply can take the safe no-model association path without becoming new evidence.
- **No-story and partial coverage:** cover greetings, name-only introductions, thanks, stop/skip instructions, vague confirmations, direct questions, explicit testimony plus a control in one reply, empty extraction, and partially linked multi-passage replies. Verify deterministically recognized non-story paths make no extraction call, meaningful unresolved testimony remains visible, an empty model response cannot settle unsupported story coverage, and independent profile evidence is not discarded. A bare yes cannot validate every proposed personal fact. An ambiguous source that required reconciliation may validly finish with an evidence-backed non-story disposition; do not hide that actual model admission.
- **Multiple events and locations:** use one reply with separate episodes, a move with origin/destination, repeated place names, an unrelated mention, and a relative's experience. Verify selective event/place roles, correct exact source spans, separate identities where required, and no all-events/all-places join. Clear later references can reuse established context; ambiguous there/then and topic changes must not inherit the last event's placement automatically.
- **Temporal grounding:** cover original English/Chinese ages, approximate years, conflicting anchors, unknown dates, life periods, valid narrator birth evidence, a relative's birth year, profile reference without sufficient evidence, and an unavailable profile update. Verify exact original expressions, supported precision/calculations, explicit uncertainty, manual corrections, and no forced age/location values. Unknown optional placement must not erase a supported event or force a new periodic profile run.
- **Selective admission and batches:** test non-milestone rounds and between-round changes, consecutive genuine story additions, a safe no-story/context-only path, bounded multi-source catch-up, oversized source pagination, Unicode spans, duplicate quotes, and partially committed batches. Observe real model admission to prove skipped/reused work does not make an unnecessary call and eligible changed evidence is not lost. No third classifier, unconditional per-reply extraction, periodic attribution schedule, or unbounded whole-history packet is allowed.
- **Mode-independence regression:** drive matched qualifying narration, safe context-only/no-story replies, mixed memory plus pacing/stop requests, and corrections through the same acceptance seam under AI comfort, explore, and shape decisions. Verify equivalent rule-based attribution, source coverage, grounded event/time/place effects, and skip/reuse decisions regardless of interview mode or a conflicting legacy phase. A mode change alone creates no reconciliation job or coverage reset; no mode-only classifier call appears. Keep actual privacy/stop handling and independent profile eligibility intact. Testing or implementing the mode selector/game guard itself belongs to Issue 76.
- **Concurrency, durability, and scope:** hold or fail B while A saves/delivers; preserve accepted-source handling after assistant failure; retry an exact turn; crash after a partial commit; resume with a fresh lease; replay a completed batch; and change source/event/policy revisions mid-flight. Verify monotonic truthful coverage, no duplicate event/link/round, restart recovery, bounded unresolved behavior, failed/stale work not reporting resolved success, and account/project isolation through actual reads and mutations.
- **Correction and role regressions:** exercise explicit placement corrections, source editing/version replacement, withdrawal, author-removed links, stage overrides, context-only association, temporal/relation dependency reuse, and later enrichment. Verify newer authority wins, affected links are invalidated safely, unrelated associations survive, withdrawn text is absent from new projections, and direct stage volume is neither inflated nor lost. Reuse real lifecycle tests and overlap/legacy-role expectations rather than invent new progress formulas.
- **Downstream and migration compatibility:** confirm composer remains a consumer of stable attribution and respects existing snapshots/protected prose, no model extraction is hidden in a periodic composer run, and unknown placement does not cause fabricated writing. Verify bounded read pagination, conservative upgrade/replay with missing legacy roles, existing two-lane flag-off behavior, and continued profile-field protection. Test outcomes supplied to Issue 76 as real pending/unresolved/committed receipts; redesigning its rendered thinking-step UI is not an additional acceptance seam for this ticket.
- **Prior art:** reuse current two-lane authenticated streaming barriers and native page commits, shared-memory event/source correction and temporal-evidence tests, bounded source-page/checkpoint recovery tests, owner-scoped collection readback, and durable stage-attribution lifecycle/provenance coverage. Historical test receipts document useful prior work but do not prove this new guarantee or current live-model behavior. No paid/live-provider campaign or access to real memoirs is authorized by publishing this spec.

## Out of Scope

- Implementing or expanding Issue 75's profile parser, locale guards, manual-confirmation controls, or periodic profile schedule.
- Implementing Issue 76's shared orchestration module, automatic interview-mode decision/game guard, full skill eligibility map, runner consolidation, or unified thinking-step UI. Supply the mode-independent attribution contract and truthful receipts it will consume.
- Adding a new skill, competing event/source store, extra foreground model classifier, or unconditional per-reply timeline/place invocation.
- Changing composer cadence, adding a periodic attribution schedule, or allowing composer to extract, merge, or retag canonical events.
- Guaranteeing an event, exact age, year, or location for every reply; inferring personal facts from map/photo metadata or forcibly resolving ambiguous testimony.
- New Family/person-identity extraction, story-game enablement, public historical research, photo search, or a new general-purpose manual attribution editor.
- Changing stage-progress percentages, free allowance, access/entitlement, consent, publication, printing, or protected-writing policy.
- Production migration/backfill, unlimited historical re-extraction, deployment, funded provider evaluations, or a live-user data audit. These require separately scoped approval and evidence.
- Broad repair of unrelated inherited tests, repository-wide renaming, physical worker mergers, or a replacement workflow/queueing platform.
