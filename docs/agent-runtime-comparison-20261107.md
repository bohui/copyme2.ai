Reviewed on 7 November 2026 against Memoir `5062ebb4` and the local `advanced_aas` checkout `d3bfc91`.

- **Mira** should run in a warm Python worker with a pooled connection to the existing Responses gateway. Start with Memoir’s guarded direct streaming helper as the benchmark candidate. Rebuild authorized history from PostgreSQL and carry over the bounded `memoir_read_context` tool for turns that need recall. Keep privacy review, streamed-field validation, cancellation, and the fenced reply commit in the application. Pydantic AI is the first framework I’d try if the candidate needs a reusable tool loop. [Direct transport](../apps/api/conversation_reply_transport.py#L71), [recall tool](../apps/api/interview_context_tools.py#L7), [Pydantic AI streaming](https://github.com/pydantic/pydantic-ai/blob/main/docs/agent.md#streaming-all-events)
- **Atlas** should keep its existing Temporal workflow. Port the Codex skill-selection loop to typed Python tools in one activity first. The bounded profile, timeline and composer phases already use direct structured Responses requests. Keep Memoir’s source-batch boundaries, leases, retry rules, prompt manifests and publication checks around the tools. [Atlas workflow](../apps/api/temporal_workflows.py#L89), [skill selection](../apps/api/memoir_background_agent.py#L275), [bounded phases](../apps/api/lifetime_memory_lane_engine.py#L860)
- **For a shared agent service across projects**, `advanced_aas` is the first candidate if you want to own the platform. Use it as a private executor behind Memoir and keep Temporal responsible for Atlas job recovery. Mastra is the strongest third-party option in this comparison when a standalone TypeScript HTTP service is the priority. ## What Memoir already measures

Mira resumes a persistent **thread** in an app-server process scoped to the turn. Native history, compaction and owner-scoped recall contribute behavior the direct HTTP helper needs to recover. The current helper’s Mira path is tool-free and used in controlled probes. Atlas runs independently with reserved foreground capacity for Mira. [Mira session](../apps/api/conversation_reply_session.py#L97), [collector dispatch](../apps/api/lifetime_memory_engine.py#L405), [two-lane behavior](../README.md#mira-and-atlas)

The 11 October profile attributed about **0.10–0.26 s** to worker initialization and thread creation. The 24 October cohort’s median time to the correct delivered response was **11.17 s → 5.55 s** across 30 cases that passed in both arms after a combined routing and reply change. The latter cohort’s policy and reply spans were both measured in seconds. These are historical observations on earlier revisions, with gateway load and cache differences. Measure those spans again before attributing a gain to a harness swap. [First-reply profile](first-reply-profiling-2026-10-11.md#isolated-collector-measurements), [24 October cohort](interviewer-stop-latency-20261024.md)

Atlas’s move from a native session to direct structured extraction reduced median validated extraction from **29.13 s to 6.64 s** in nine historical scenarios. The comparison had one sample per scenario, with different cache usage and some changes to the number of attempts. That direct path is already in the checkout. [Timeline comparison](author-timeline-latency-20261024.md#retained-main-beforeafter-comparison)

## Where `advanced_aas` fits

The local code has a Fastify bridge with SSE and WebSockets, JWT options, configurable session persistence, a streaming provider interface, and A2A task state. This gives an owned service a head start. Memoir’s Supabase-backed permissions, history and commits should remain authoritative, including across interrupted turns. [Bridge](/Users/bohuihan/ai/advanced_aas/docs/api-bridge.md), [provider interface](/Users/bohuihan/ai/advanced_aas/packages/core/src/providers/protocol.ts:48)

Two implementation details determine its fit for these lanes.

- The default `GatewayProvider` uses **Chat Completions**. Memoir uses **Responses** with strict JSON schemas and request provenance. The default provider also checks `abortSignal` while iterating received chunks, after opening the HTTP stream without passing it to the SDK. A Memoir adapter should preserve the Responses contract and pass cancellation through the transport, with bounded retries and tests for a stalled upstream. [AAS gateway](/Users/bohuihan/ai/advanced_aas/packages/core/src/providers/gateway.ts:75), [Memoir request shape](../apps/api/conversation_reply_transport.py#L71)
- A2A persists task status, but runs execute in process. Startup reconciliation marks eligible orphaned tasks failed. Keep Atlas’s Temporal activity recovery and idempotent database writes as the job contract if AAS serves the model loop. [Task executor](/Users/bohuihan/ai/advanced_aas/packages/api-bridge/src/server/a2a-task-service.ts:483), [startup reconciliation](/Users/bohuihan/ai/advanced_aas/packages/api-bridge/src/server/AgentBridgeServer.ts:254)

The supplied GitHub URL returned 404 through the available connection, so this review uses the local source. The checked-out revision has no explicit repository license file or package license declaration to establish open-source reuse terms.

## External candidates

The comparison treats “stands” as Strands Agents and “deepagent” as LangChain Deep Agents. The rankings reflect fit with Memoir’s architecture. Comparative latency remains to be measured.

| Candidate | Fit for Memoir |
| --- | --- |
| **Pydantic AI** | MIT Python SDK with typed tools and outputs, streaming and an OpenAI Responses adapter that can target the existing gateway. This is the closest framework fit for the current Python worker. Temporal integration is available if a future Atlas activity needs to checkpoint individual model or tool calls in a workflow. For the first port, the existing activity boundary already provides durable retries. [License](https://github.com/pydantic/pydantic-ai/blob/main/LICENSE), [Responses adapter](https://pydantic.dev/docs/ai/models/openai/#custom-openai-client), [Temporal integration](https://pydantic.dev/docs/ai/capabilities/durable_execution/temporal/) |
| **Mastra** | Apache-2.0 core with a self-hosted TypeScript server for streaming agent and workflow APIs. Workflow suspension persists snapshots. For Memoir, that service is an option if a shared HTTP API justifies a separate runtime. Its enterprise directories have separate license terms. [Server](https://mastra.ai/docs/server/overview), [workflow snapshots](https://mastra.ai/docs/workflows/suspend-and-resume), [license](https://github.com/mastra-ai/mastra/blob/main/LICENSE.md) |
| **Strands Agents Harness SDK** | Apache-2.0 SDK with Python async event streaming and pluggable session storage. Embed the SDK directly in a worker with just Memoir’s tools. It is a good Python option for Mira and typed Atlas activities. The SDK’s execution checkpoint API is experimental. Continue using Temporal for Atlas job recovery. [SDK](https://github.com/strands-agents/harness-sdk), [async streaming](https://strandsagents.com/docs/user-guide/sdk/streaming/async-iterators/), [deployment](https://strandsagents.com/docs/user-guide/sdk/deploy/), [checkpoint API](https://strandsagents.com/docs/api/python/strands.experimental.checkpoint.checkpoint/) |
| **Pi** | MIT TypeScript toolkit. `@earendil-works/pi-agent-core` provides an in-process streaming tool loop for a Node service. The coding-agent SDK and stdio RPC add coding-oriented sessions and tools. Experimental Pi Durable can resume model and tool execution after a crash, with explicit replay rules for tools. Standard Pi is the lean TypeScript comparator, and Pi Durable can be evaluated separately if Atlas later needs tool-level resumption. [Repository](https://github.com/earendil-works/pi), [agent core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md), [RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md), [Pi Durable](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md) |
| **DeepSeek Harness** | Official MIT TypeScript/Cordis harness in developer preview. Its Python SDK reuses a `dsh` subprocess over stdio JSON-RPC. The server streams session events, and the shipped minimal profile saves local JSONL sessions. This is a viable harness experiment behind the existing worker boundary. For Memoir, remove the minimal profile’s unrestricted shell, disable its default session-log uploads with `session-log-deepseek.enabled: false`, and isolate its workspace and home. [Repository](https://github.com/deepseek-ai/deepseek-harness), [release history](https://github.com/deepseek-ai/deepseek-harness/releases), [Python SDK profile](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/python-sdk.md#understand-the-minimal-profile), [SDK transport](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/server/README.md) |
| **LangChain Deep Agents** | MIT Python harness with a virtual filesystem and subagents, plus optional planning and skills. A persistent LangGraph checkpointer can restore a thread. Consider this for a specific Atlas research job that benefits from delegation, alongside the current Temporal workflow. LangSmith’s standalone production Agent Server requires a LangSmith license key. An open-source deployment can host the SDK inside Memoir. [License](https://github.com/langchain-ai/deepagents/blob/main/LICENSE), [SDK](https://docs.langchain.com/oss/python/deepagents/overview), [persistence](https://docs.langchain.com/oss/python/langgraph/persistence), [Agent Server requirements](https://docs.langchain.com/langsmith/deploy-standalone-server) |
| **OpenCode** | MIT coding harness with a documented headless HTTP server, OpenAPI, SSE, async prompt submission, and session abort. It is a practical external service comparator if HTTP integration is the priority. The published API has server-wide basic auth and an event feed for all projects, so Memoir would supply tenant authorization and Atlas job durability. [License](https://github.com/anomalyco/opencode/blob/dev/LICENSE), [server API](https://docs.opencode.ai/docs/server/) |
| **Dify** | Self-hosted application builder with streaming REST APIs and API keys scoped to each app. Its modified Apache terms allow commercial backend use and require written authorization to operate multiple Dify workspaces as a multi-tenant service. This makes it a poor fit for a requirement for an unrestricted open-source platform. [API guide](https://docs.dify.ai/en/api-reference/guides/get-started), [license](https://github.com/langgenius/dify/blob/main/LICENSE) |

## First benchmark

1. Compare current Codex with direct Responses through the same gateway alias, effective reasoning, prompt pins and output schema. Hold the authorized context constant where possible and log actual input tokens, cache hits and request counts. Use a controlled provider first to isolate transport overhead, then interleave live synthetic runs to limit provider load drift. Compare Flash separately on the selected runtime.
2. Replay English and Chinese openings, rich stories, resumes and recall, privacy exclusions, corrections and interruption. Test with Atlas active. Time source acceptance, policy review, first meaningful text, validated next question and durable save separately. Include cold and warm runs, retries and failures. Use the project’s **5 s** meaningful-text target and **10 s** fallback as comparison thresholds and report tail percentiles only with enough samples. [Latency definition](Memoir_Conversational_Response_Latency_Spec.md#implementation-decisions), [project targets](issue53-live-latency-20261020.md#issue-53-collector-latency-and-release-evidence)
3. Port a single Atlas source batch. Kill the activity worker during tool execution and around the durable commit. Check that the same source batch resumes or retries, committed work appears once, stale or cross-owner work cannot publish, and Mira still streams on reserved capacity. Track queue wait and commit latency separately from provider time. [Background workflow tests](../tests/test_memoir_background_agent_workflow.py)
